Build a Notion integration layer for my existing internal AI app in Replit.

CONTEXT
I already have a working AI assistant that can read uploaded documents and answer questions. Do NOT rebuild the AI system, RAG pipeline, document upload flow, or chat interface from scratch.

The goal is to extend the existing app so it can connect to Notion and let authorized users view, search, create, and update tickets in a Notion database.

OBJECTIVE
Add Notion ticket read/write capabilities to the current app so that:
- users can view and search tickets from Notion
- the app can open and display a ticket’s details
- authorized users can create tickets
- authorized users can update ticket properties
- the app can append notes or summaries to ticket pages
- the existing AI can draft ticket updates, but writes must happen only through controlled backend actions

DO NOT REBUILD
- do not rebuild the current AI assistant
- do not replace the current chat system
- do not rebuild document retrieval
- do not create a second AI architecture
- do not create a separate knowledge base

ONLY ADD
- Notion integration
- ticket read/write endpoints
- permission checks for writes
- optional UI components/pages for ticket actions
- audit logging

STACK
Use the existing stack already in the project.
If needed, add:
- Notion API
- PostgreSQL tables for audit logs and optional draft tracking
Keep all secrets server-side.

NOTION FEATURES TO ADD
1. Read tickets from a specified Notion database
2. Search/filter tickets by:
   - title
   - status
   - owner
   - priority
   - tags
3. Open a ticket and display:
   - properties
   - page content / notes
4. Create a new ticket
5. Update ticket properties:
   - status
   - owner
   - priority
   - tags
   - due date
6. Append notes or summaries to the body of a Notion ticket page

PERMISSIONS
Implement app-level authorization for Notion writes:
- admin: can create and update tickets
- user: can view/search tickets and generate draft updates, but cannot apply writes unless explicitly permitted
All write actions must be enforced server-side.
Do not rely only on the frontend for access control.

AI WORKFLOW
My existing AI should remain the source of suggestions.
The integration should support this flow:
1. User asks the existing AI to draft a ticket update or summary
2. The app shows the draft to the user
3. If the user is authorized and confirms, the backend writes the approved update to Notion

The AI itself should not directly call Notion from the client.

AUDIT LOGGING
Add audit logging for all Notion write actions:
- user email
- action type
- notion page ID
- timestamp
- short summary of what changed

Optionally add a table for AI-generated drafts:
- user email
- ticket ID
- draft type
- draft content
- approved_at nullable

ENV VARS
Add support for:
- NOTION_API_TOKEN
- NOTION_DATABASE_ID

PAGES / ROUTES
Integrate with the existing app and add only what is necessary, such as:
- /tickets : ticket list/search page
- /tickets/[id] : ticket detail page
- /api/notion/tickets : list/search tickets
- /api/notion/tickets/[id] : get one ticket
- /api/notion/tickets/create : create ticket
- /api/notion/tickets/update : update ticket
- /api/notion/tickets/append-note : append note to ticket
- /api/notion/drafts/approve : approve AI draft and write to Notion

IMPLEMENTATION REQUIREMENTS
- Reuse existing auth/session logic if already present
- Reuse existing UI patterns if already present
- Keep the Notion token server-side only
- Do not log secrets
- Return clear error messages for unauthorized actions
- Build this as an extension of the current app, not a separate app

OUTPUT
1. Modify the existing project rather than scaffolding a new one
2. Add the necessary server utilities for Notion API access
3. Add minimal UI for ticket list/detail/create/update
4. Add setup instructions for connecting the Notion integration to the target database
5. Explain where the new files were added and how they connect to the existing app
